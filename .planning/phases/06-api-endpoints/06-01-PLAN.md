# PLAN-01: Health Check API Endpoints

**Wave:** 1
**Depends on:** None (Phase 5 complete)

## Goal

Expose Linear health check functionality via REST API endpoints with caching for rate limit compliance.

## Implementation

### Step 1: Add POST /api/integrations/linear/test-connection endpoint

In `spectrace/requirements/api.py`:
- Add `_compute_overall_status()` function implementing worst-case-wins logic
- Add `_result_to_dict()` helper to serialize TestConnectionResult to JSON
- Add `test_linear_connection()` view function with @csrf_exempt and @require_http_methods(["POST"])
- Call `verify_linear_connection()` from health.py
- Cache results with 60-second TTL using Django cache framework
- Return JSON response with success, message, status, checks, error_details, cached fields

### Step 2: Add GET /api/integrations/linear/health endpoint

In `spectrace/requirements/api.py`:
- Add `get_linear_health()` view function with @require_http_methods(["GET"])
- Retrieve cached health data from Django cache
- Return cached result with cached=True flag if available
- Return status=unknown with cached=False if no cached data exists

### Step 3: Configure URL routes

In `spectrace/spectrace/urls.py`:
- Add URL pattern for `api/integrations/linear/test-connection/`
- Add URL pattern for `api/integrations/linear/health/`
- Wire to api module view functions

### Step 4: Add comprehensive tests

In `spectrace/requirements/tests/test_api.py`:
- TestLinearTestConnectionAPI class with tests for:
  - All checks pass returns healthy status
  - Auth fails returns degraded status
  - Config fails returns unhealthy status
  - Invalid JSON returns 400
  - Request body overrides settings
  - Result is cached after test
- TestLinearHealthAPI class with tests for:
  - No cached result returns unknown status
  - Cached result is returned with cached=True
  - Health returns result from prior test-connection call
