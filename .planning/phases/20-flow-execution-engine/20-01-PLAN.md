- Read config: `seconds` (default 1)

- Always passes (unless interrupted)

Extend `SequentialFlowEngine` in `engine.py`:

**Add timeout exceptions:**
```python
class StepTimeoutError(Exception):
    """Step exceeded its timeout."""
    pass

class FlowTimeoutError(Exception):
    """Flow exceeded its total timeout."""
    pass
```

**Add timeout context manager:**
- Use `signal.alarm()` for POSIX systems
- Implement `_step_timeout_context(self, seconds: int)` as context manager
- Check `sys.platform` - on Windows, skip signal-based timeout (document limitation)

**Modify `execute()` method:**
- Add parameters: `step_timeout: int = 60`, `flow_timeout: int = 300`
- Track `flow_start = datetime.now(UTC)` at beginning
- **Critical:** Filter metadata from steps: `steps = [s for s in flow.steps if '_metadata' not in s]`
- For each step:
  1. Check flow timeout (elapsed > flow_timeout)
  2. Get step type: `step_type = step_def.get('type', 'handler')`
  3. Use step type dispatcher instead of direct `load_handler()`:
     - Import `execute_step` from `requirements.flows.executors`
     - Call `execute_step(step_def, context)` within timeout context
  4. Catch `StepTimeoutError` and record as failed step
- Keep existing early-exit-on-failure behavior
- Keep existing context sanitization

**Backward compatibility:**
- Existing `type='handler'` steps must work exactly as before
- Existing tests must pass without modification
