**Content Sections (progressive disclosure):**

**Section 1: What is SpecTrace?**
- One-line value prop: "See which requirements are verified by passing tests"
- Brief explanation: Requirements as code, automatic verification, no manual tracking
- Link to about.html for deep dive

**Section 2: The Three-Step Workflow**
- Visual workflow diagram or numbered steps:
  1. Write specs as markdown files
  2. Link tests with pytest markers
  3. View verification status in dashboard

**Section 3: Step 1 - Write Your First Spec**
- Explanation: Specs are markdown with YAML frontmatter
- Copy-paste code example using Alpine.js pattern from spectrace_overview.html:
  ```
  <div class="code-block" x-data="{ copied: false }">
    <button class="copy-btn" @click="navigator.clipboard.writeText($refs.code.textContent); copied = true; setTimeout(() => copied = false, 2000)">
      <span x-show="!copied">Copy</span>
      <span x-show="copied">Copied!</span>
    </button>
    <pre x-ref="code">---
id: REQ-AUTH-001
title: User Login
priority: high
verification_method: test
---

Users must authenticate with email and password.</pre>
  </div>
  ```
- Note file location: specs/auth.md
- Command to import: python spectrace/manage.py parse_specs specs/

**Section 4: Step 2 - Link Tests with Pytest Markers**
- Explanation: Use @pytest.mark.requirement() decorator
- Copy-paste code example (from test_sample_requirements.py):
  ```python
  import pytest

  @pytest.mark.requirement("REQ-AUTH-001")
  def test_user_can_login():
      """Test successful login with valid credentials."""
      # Your test logic here
      assert True
  ```
- Command to extract links: python spectrace/manage.py extract_links --output links.json
- Command to run tests: pytest --junitxml=test_results.xml

**Section 5: Step 3 - View Dashboard Results**
- Explanation: Import results and view status
- Commands:
  - python spectrace/manage.py import_results test_results.xml --links links.json
  - python spectrace/manage.py runserver
  - Open http://localhost:8000/admin/
- Expected result description:
  - Green badge = requirement verified by passing tests
  - Red badge = requirement has failing tests
  - Gray badge = requirement has no linked tests
  - Dashboard shows traceability matrix with all requirements
- Screenshot placeholder or detailed text description of dashboard

**Section 6: Next Steps**
- Link to traceability matrix: {% url 'admin-matrix' %}
- Link to about page for concepts: {% url 'admin-about' %}
- Link to verification flows: {% url 'admin-flow-status' %}
- Link to guided tour: Start tour from landing page

**Styling:**
- Use .st-* design system classes (st-surface, st-border, st-text, st-accent-500)
- Match landing.html aesthetics (centered layout, card-based sections)
- Dark mode support (html.dark selectors)
- Responsive: single column on mobile, max-width: 900px
- Code blocks: monospace font, syntax-like appearance, copy button top-right
- Section spacing: var(--st-space-8) between sections

**Alpine.js:**
- Load Alpine.js from CDN (defer script)
- Use x-data for copy button state management
- No additional JavaScript needed beyond copy-to-clipboard

**Why this approach:**
- Progressive disclosure reduces overwhelm (What → Why → How → See It Working → Next Steps)
- Copy-paste examples lower friction (users don't type, they paste)
- Expected results show success state (users know if they did it right)
- Links to deeper content support power users without cluttering onboarding
