Spec Syntax Guide

Write precise, testable requirements using FRET-inspired structured fields. Better specs lead to better tests.

What is FRET?

FRET (Formal Requirements Elicitation Tool) is a NASA tool for writing unambiguous requirements. SpecTrace adapts FRET's structured approach for practical use in product specs.

SCOPE CONDITION COMPONENT shall TIMING RESPONSE

"When in scope, if condition, the component shall within timing respond."

Why Structure Matters
Structured fields enable automated analysis: conflict detection, timing validation, and completeness scoring. Vague requirements hide bugs.

Structured Fields

All fields are optional. Use what makes sense for each requirement. More fields = higher completeness score = better automated analysis.

Field Question Example
scope When does this apply? when in active_session
condition What triggers it? battery_level < 10%
component What system owns this? notification_service
timing Performance constraint? within 2 seconds
response What must happen? display low_battery_warning
Completeness:
60% (3 of 5 fields)

Spec File Format

Requirements are written as Markdown files with YAML frontmatter. Store them in a specs/ directory in your repo.

Basic Structure

specs/auth/login.md
--- id: REQ-AUTH-001 title: User Login priority: high status: active verification_method: test tags: - auth - security --- Users must be able to log in with email and password. ## Acceptance Criteria - Email validation on submit - Password minimum 8 characters - Session created on success - Error shown on invalid credentials

With Structured Fields

specs/notifications/battery_warning.md
--- id: REQ-NOTIF-042 title: Low Battery Warning priority: high status: active verification_method: both # FRET-style structured fields scope: when in active_session condition: battery_level < 10% component: notification_service timing: within 2 seconds response: display low_battery_warning AND vibrate_device --- The system must warn users when battery is critically low during an active session to prevent data loss. ## Rationale Users often ignore battery warnings. Combining visual and haptic feedback increases awareness.

Hierarchical Requirements

specs/mobile_key/index.md (parent)
--- id: REQ-MKEY-000 title: Mobile Key Feature status: active --- Mobile key enables guests to unlock doors with their phone.
specs/mobile_key/provisioning.md (child)
--- id: REQ-MKEY-001 title: Key Provisioning parent: REQ-MKEY-000 status: active component: key_provisioning_service --- Keys are provisioned after check-in confirmation.

Frontmatter Reference

Required Fields

Field Type Description
id string Unique identifier (e.g., REQ-AUTH-001)
title string Short descriptive title

Metadata Fields

Field Values Description
status draft, active, deprecated Lifecycle state (default: draft)
priority high, medium, low Business priority
verification_method test, inapp, both How to verify (default: unspecified)
tags list Category tags for filtering
parent string Parent requirement ID for hierarchy

FRET Structured Fields

Field Type Example
scope text when user_is_authenticated
condition text request_count > rate_limit
component string rate_limiter
timing string immediately, within 500ms
response text return HTTP 429 AND log_event

Writing Tips

Use Active Voice
Good: "The system displays an error message"
Bad: "An error message is displayed by the system"
Be Specific About Timing
Good: timing: within 200ms
Bad: timing: quickly
Name Components Consistently
Use snake_case for component names. Match your codebase naming. Examples: auth_service, payment_gateway, notification_queue
Express Conditions as Predicates
Write conditions that can be evaluated as true/false.
Good: user.role == 'admin' AND feature_flag.enabled
Bad: when appropriate

Conflict Detection

Structured fields enable automated conflict detection between requirements:

Conflict Type What It Detects
Condition Overlap Two requirements with overlapping conditions but different responses
Timing Conflict Incompatible timing constraints on the same component
Response Contradiction Same condition triggers contradictory responses
Run Conflict Detection
python manage.py detect_conflicts --alert
