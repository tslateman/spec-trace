About SpecTrace

Modern requirements traceability for Python teams

Connect product specs to verified code. See what's tested, what's verified, what's working.

What is Requirements Traceability?

Requirements traceability is the ability to track requirements through the entire development lifecycle — from specification through implementation to testing. It answers critical questions: "Is this requirement implemented?" "Which tests verify this feature?" "What breaks if I change this spec?"

SpecTrace brings requirements traceability to Python projects with specs-as-code, pytest integration, and a live dashboard showing verification status.

Core Capabilities

📝

Requirements live in your repo as markdown files. Version controlled, reviewable, no drift.

🔗

Test Linking

✅

Verification Status

Live dashboard shows which requirements are passing, failing, or untested.

🌳

Hierarchical

Organize requirements in parent-child trees. Efficient materialized path queries.

💥

Impact Analysis

See which tests are affected when specs change (git diff integration).

📊

Traceability Matrix

Visual grid of requirements × tests with color-coded verification status.

Why Requirements Traceability Matters

❌ Without Traceability

  • Specs scattered across Slack, Notion, Linear
  • No single source of truth
  • Can't answer "is REQ-X working?"
  • Tests may verify wrong behavior
  • Coverage gaps go unnoticed
  • Specs drift from implementation

✅ With SpecTrace

  • Specs version-controlled with code
  • Single source of truth in repo
  • One-click verification status
  • Explicit requirement ↔ test links
  • Dashboard highlights coverage gaps
  • Specs stay in sync via git workflow

Key Concepts

Requirement
Product spec parsed from markdown with unique ID (REQ-XXX-001). Organized hierarchically with parent-child relationships.
Verification Status
Passing: All linked tests pass | Failing: Any test fails | Untested: No tests linked
Traceability
Bidirectional links between requirements ↔ tests. Navigate from requirement to tests, or from test to requirements.
Impact Analysis
Git diff integration shows which tests are affected when specs change. Helps target test runs efficiently.

Getting Started

1. Create a Spec File

Create specs/auth.md with YAML frontmatter:

--- id: REQ-AUTH-001 title: User Login priority: high verification_method: test --- Users must be able to log in with email and password. ## Acceptance Criteria - Email validation - Password strength requirements - Session creation on success

2. Import Specs

Parse markdown files into the database:

python manage.py parse_specs specs/

3. Link Tests

Annotate pytest tests with requirement IDs:

import pytest @pytest.mark.requirement("REQ-AUTH-001") def test_user_can_login(): """Test successful login with valid credentials.""" # Test implementation pass @pytest.mark.requirement("REQ-AUTH-001", "REQ-AUTH-002") def test_login_creates_session(): """Test can link to multiple requirements.""" pass

4. Run Tests & Import Results

Run pytest and import results to see verification status:

pytest --junitxml=results.xml python manage.py extract_links -o links.json python manage.py import_results results.xml --links links.json

5. View Dashboard

Open the dashboard to see real-time verification status:

python manage.py runserver # Open http://localhost:8000/admin/

Advanced Features

🏢 Vendor Coverage

Track integration validation by vendor (PMS systems, mobile keys, payment gateways). See pass rates per vendor.

📱 In-App Validation

SDK for validation buttons in production apps. Multi-step validations with granular pass/fail tracking.

🎯 SLO Integration

Link requirements to Service Level Objectives using OpenSLO YAML. Track operational compliance.

🔌 REST API

Push validation results from external systems. Submit status updates, retrieve requirement status.

🔍 Conflict Detection

FRET-inspired structured fields enable condition overlap, timing conflict, and response contradiction detection.

📈 Linear Integration

Sync with Linear issues. Track requirement-to-issue mapping with health checks and auto-enrichment.

Tech Stack

Core Technologies

  • Django 5.2 LTS — Web framework
  • django-treebeard — Hierarchical requirements storage
  • django-unfold — Modern admin UI with Tailwind CSS
  • pytest — Test framework with requirement markers
  • SQLite/PostgreSQL — Database (SQLite dev, Postgres prod)

Design Philosophy

  • Specs in codebase, not Notion — version control
  • Markdown format — PM-friendly, reviewable
  • pytest markers — native to workflow
  • Denormalized status — fast dashboard reads
  • Materialized path — efficient tree queries
