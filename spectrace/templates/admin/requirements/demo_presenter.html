Agent Claims Work

The agent registers and picks up a task

# Register the agent with the system
$ spectrace agent register my-claude-agent
Agent registered: my-claude-agent

# List available tasks (unverified requirements)
$ spectrace agent tasks
┌─────────────────────┬───────────────────────────────┬──────────┐
│ ID                  │ Title                         │ Priority │
├─────────────────────┼───────────────────────────────┼──────────┤
│ REQ-UPGRADE-001     │ Guest Room Upgrade Request    │ medium   │
│ REQ-UPGRADE-002     │ Upgrade Status Check          │ low      │
│ REQ-UPGRADE-003     │ Cancel Upgrade Request        │ low      │
└─────────────────────┴───────────────────────────────┴──────────┘

# Claim a task to work on
$ spectrace agent claim REQ-UPGRADE-001
Claimed: REQ-UPGRADE-001 - Guest Room Upgrade Request

# Start working (creates branch, loads context)
$ spectrace agent start
Branch: agent/REQ-UPGRADE-001
Ready to implement. Spec loaded to context.
Presenter Notes

The agent pipeline provides structure: register, claim, start. Each step is atomic and auditable. The branch naming convention makes it easy to track what's in progress.

3

Implementation

Agent writes tests that reference the requirement

tests/test_upgrade_service.py 
import pytest
from services.upgrade import UpgradeService


# The magic: linking test to requirement
@pytest.mark.requirement("REQ-UPGRADE-001")
def test_create_upgrade_request__returns_request_id():
    """Returns request_id when upgrade request created."""
    service = UpgradeService()
    result = service.create_request(
        reservation_id="RES-123",
        requested_room_type="suite"
    )
    assert result.request_id is not None
    assert result.status == "PENDING"


@pytest.mark.requirement("REQ-UPGRADE-001")
def test_create_upgrade_request__fails_invalid_reservation():
    """Fails with INVALID_RESERVATION if not found."""
    service = UpgradeService()
    with pytest.raises(InvalidReservationError):
        service.create_request(
            reservation_id="DOES-NOT-EXIST",
            requested_room_type="suite"
        )
  • @pytest.mark.requirement creates the traceability link
  • Test names follow the test_method__expected_behavior convention
  • Each acceptance criterion gets its own test
Presenter Notes

The pytest marker is the key. It creates a machine-readable link between the test and the requirement. When tests pass, we know the requirement is verified.

Presenter Notes

Invariant checks catch common mistakes before review. This saves reviewer time and ensures consistency across all agent work.

$ spectrace agent merge

Merge checklist:
✓ PR approved by lead-developer
✓ CI pipeline passed
✓ No merge conflicts
✓ Invariants still satisfied

Merged to main. REQ-UPGRADE-001 now VERIFIED.

# Update traceability matrix
$ spectrace sync
Dashboard updated. 1 requirement verified.
Presenter Notes

Human stays in the loop for approval. The agent handles the tedious parts (PR creation, merge mechanics) but can't merge without human sign-off.
