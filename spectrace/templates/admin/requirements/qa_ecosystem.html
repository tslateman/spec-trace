How SpecTrace Fits

SpecTrace answers a single question: which requirements pass, which fail, and which remain untested?

What SpecTrace Does

The six components that trace requirements to tests

Component Purpose
Specs Parser Reads requirements from markdown with YAML frontmatter
Test Linking Connects tests to requirements via @pytest.mark.requirement("REQ-XXX")
In-App Validation SDK Verifies integrations in production (e.g., "Test PMS Connection")
SLO Integration Imports OpenSLO definitions and tracks compliance
Verification Status Computes requirement status from test results: passing, failing, untested
Risk Classification Marks requirements as critical, high, medium, or low

Core workflow:

Specs (markdown) → Test markers → JUnit results → SpecTrace → Coverage matrix

Integration Points

SpecTrace adds value to each initiative

PR Smoke Tests

Run tests on critical paths Specs define criticality via risk: critical
5-10 smoke scenarios Maps scenarios to requirements
Actionable PR feedback Links failures to business requirements

Ephemeral Environments

QA seed data in snapshots In-app validation confirms seed data meets test prerequisites
Consistent environment setup Health checks verify environment before tests run

Mutation Testing

Which code to mutation test? Prioritizes code backing critical requirements
Track test effectiveness Correlates mutation scores with requirement coverage

Configuration Conformity

Validate config changes Express consistency predicates as requirements
Enforce portfolio rules Track conformity status per hotel
Detect drift Flag hotels diverging from portfolio settings
