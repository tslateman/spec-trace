# Current State

> SpecTrace: Requirements traceability for Python projects
> Last updated: 2026-09-16 (Cloudflare port, phases 0-4 shipped)

## What Exists

SpecTrace connects markdown specs to pytest tests and reports verification
status. Public repo: `tslateman/spec-trace`.

Three deployables:

| Part               | Runtime            | Owns                                                                    |
| ------------------ | ------------------ | ----------------------------------------------------------------------- |
| Worker (`worker/`) | Cloudflare Workers | The v1 API (43 operations), D1, the TaskLedger DO, the public demo page |
| Dashboard (`app/`) | Cloudflare Workers | React screens behind GitHub OAuth, reading the Worker                   |
| CLI (`spectrace/`) | Dev machines, CI   | Parsing specs, tests, and git; pushing what it reads                    |

The Worker serves production at `spectrace.spectrace.workers.dev`, and CI
deploys it on merge to main. The dashboard runs at
`spectrace-app.spectrace.workers.dev`. The Django server in `spectrace/` still
runs locally and is being retired; it has not been stopped. The Worker's old
data-screen URLs redirect to the dashboard, so requirement data sits behind
GitHub OAuth. One public demo page stays at `/demo/`; the two older demo
screens redirect to it.

See [plans/cloudflare-port.md](../plans/cloudflare-port.md) for the phase status.

## Agent Task Pipeline

Blackboard architecture for agent coordination. See
**[docs/agent-tasks.md](agent-tasks.md)** for complete documentation.

**State machine:**

```
DRAFT -> UNCLAIMED -> CLAIMED -> IN_PROGRESS -> READY_FOR_REVIEW -> APPROVED -> MERGED
                 ^                                     |
                 +------ CHANGES_REQUESTED <-----------+
```

**CLI commands:** every one calls the Worker's task ledger.

```bash
spectrace tasks register <name> --role planner|coder|reviewer
spectrace tasks create <task_id> --title <title> --agent <planner_id>
spectrace tasks approve-spec <task_id> --reviewer <id>
spectrace tasks list [--status unclaimed]
spectrace tasks claim <task_id> --agent <agent_id> [--lease-minutes 30]
spectrace tasks start <task_id> --agent <agent_id>
spectrace tasks validate-intent <task_id> --commit-sha <sha> ...
spectrace tasks complete <task_id> --agent <agent_id> --commit-sha <sha>
spectrace tasks review <task_id> --reviewer <id> --decision approved|changes_requested
spectrace tasks merge <task_id>
spectrace tasks run --coder <command> --tests <command>
```

The Durable Object's alarm expires a lapsed lease, so no scheduled command does.

## Quick Reference

```bash
# Setup
just install-dev && just migrate && just setup

# Run
just run                                      # Start dev server
just test                                     # Run tests (excludes demo markers)
just check                                    # lint + format + test (matches CI)

# Push specs, links, and flows to the Worker
python spectrace/manage.py extract_links --path spectrace --output links.json
spectrace push --specs specs --specs meta/specs --flows flows --links links.json --replace

# Push a test run
pytest --junitxml=test_results.xml
spectrace results push test_results.xml --links links.json

# Coverage, drift, impact
spectrace specs coverage
spectrace specs drift --tests spectrace --specs specs
spectrace specs impact HEAD~5 HEAD

# Agent task workflow
spectrace tasks register coder-1 --role coder
spectrace tasks list --status unclaimed
spectrace tasks claim task-001 --agent coder-1
spectrace results invariants                  # Validate consistency

# Regenerate this document's live-state block from the Worker
spectrace consolidate

# Worker and dashboard
just worker-test                              # Worker tests
just app-dev-local                            # Both Workers against local D1

# View the dashboard
open https://spectrace-app.spectrace.workers.dev/
```
